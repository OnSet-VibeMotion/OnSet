## {{STAGE:visual-qc}}：首帧封面和视觉验收

用于抖音等竖屏平台时，第 0 帧必须是可直接作为封面的完整画面：

- 使用已确认的封面标题，严格保持文字、行数和标点。
- 第 0 帧不能是黑帧、空白帧、半透明过渡态或尚未完成的动画状态。
- 标题位于安全区，无遮挡、无裁切，并与背景保持足够对比度。
- 标题至少稳定若干帧后再开始转场；稳定帧数写入项目配置和视觉检查表。
- 对第 0 帧、转场开始帧和转场进行中的代表帧截图检查。
- 眼镜、连线、图标、人物或其他核心视觉隐喻必须检查几何形状、对齐和语义是否正确。

批量视觉验收优先用 `scene_frames_batch({"scenes": "scenes/", "out": "production/visual-qc/batch", "check_blank": true})` 一次性完成全片空白帧检测，并把每 5 个镜头拼成一张总览联系表（每行一镜，含首、中、末帧）。**先看总览联系表**：只在总览表发现异常、需要核对第 0 帧封面细节或排查特定动作时，再对单个镜头调用 `scene_frames({"scene": "<镜头目录>", "out": "production/visual-qc/<镜头编号>", "report_json": "production/visual-qc/<镜头编号>.json"})`（不要自己拼 FFmpeg，也不要逐镜打开 20 张单镜联系表）。参数 `at` 接受秒数、百分比和 `end`，可混用；`end` 取时长减一帧，直接用时长会超出末帧，FFmpeg 会返回成功却什么都不输出。

看图的顺序：先看 `scene_frames_batch` 的总览联系表；单镜补查时先加 `"sheet": true` 看单镜联系表，只在看出问题、或要确认某处细节时，再打开那一张单帧或用 `crop` 看局部，不要逐张打开每一帧。抽出的单帧缺省是缩小的（宽 960），够看构图、有没有画面、字幕在不在。渲染工具交付前已经自查过画面，这里看的是镜头之间、镜头与任务书之间对不对得上。看过的每张图都会一直留在你的上下文里，后面每一步都要重读。

静帧看不出动作。入场、阶段切换和转场用 `"strip": "开始:结束"` 把该段每一帧拼成一张条带图，检查有没有一帧蹦出或闪烁、是否全程匀速、几个元素是否同一帧齐动、上一个信息点读完前下一个是否已经抢视线。小字号文字用 `"crop": "x,y,宽,高"` 在原始分辨率下看清楚，不要凭缩略图判断可读。

第 0 帧要做封面时加 `"at": "0", "check_blank": true`，空白帧直接判失败。判定阈值刻意保守，只拦几乎完全均匀的画面：深色背景配浅色标题是常见设计，偏暗但有内容的帧只进报告的 `hints`，不影响退出码。

命令只负责把 MP4 变成可以逐张打开看的 PNG，并标出纯色帧这种机器能判的情况。画面对不对要你自己看图判断——上面列的几何、对齐和语义检查没有任何机器替代。

镜头代码定稿、`visible-event-inventory.json` 按实际 composition 填好后，用一条命令核对阅读时间和同时出现的元素（卡点片没有短语时间轴，短语绑定与顺序检查会自动跳过）：

```bash
validate_reads({"report_json": "production/visual-qc/reads-check.json"})
```

`problems` 必须为空：不够读的元素在 `prompt.md` 记下证据，派发渲染器延长可读区间或拆开信息点，不得只改清单里的数字。`hints` 里「同时开始可读」的元素要确认它们是同一个信息点（如一组卡片），否则交给渲染器错开出场。

### 画面文字对账

渲染工具只看得到本镜头的字幕，为了填满图表和读数面板时会补出原文里没有的数字。所有镜头定稿后，逐镜头列出画面上出现的每个数字（含百分比、年份、版本号与单位）、型号、产品名、人名和引语，逐条对回 `story.md` 与原文，写进 `production/visual-qc/onscreen-facts.json`：每条记录镜头编号、画面上的写法和原文出处片段；纯装饰的读数（HUD 刻度、时间码、坐标）标为装饰，不写出处。

- 找不到出处的条目改画面，不改文章，也不在清单里补一个出处。
- 图表的刻度、比例和排序必须与出处数值一致；原文只给了定性描述的，不画带刻度的图表。
- 装饰读数不得带有会被读成事实的标签或单位（如「准确率 98.7%」）。
- 跨镜头重复出现的同一个量，写法和数值必须一致。
- 对账跟着镜头走：镜头有增减、重渲染，或画面文字改过，都要重做受影响镜头的条目，不得沿用上一版的 `onscreen-facts.json`。交给用户审批的候选必须已经通过对账。

把截图、检查结果和修复记录保存在 `production/visual-qc/`。视觉未通过时，只重渲染相关镜头，不重做已确认的网格和其他镜头。

视觉验收不能只看静态构图，还必须检查：

- 每个关键文字在实际候选视频中的前一帧、开始帧和稳定帧，以及它是否落在预定的拍上。
- clip 窗口与 GSAP 淡入、停留、淡出是否真实相交。
- 同一位置替换的文字是否按 `story.md` 的顺序出现，是否残留上一词或提前显示下一词。
- 动画速度是否连续。出现卡顿时先检查是否做过二次时间映射、像素级变速、重复帧或极短 clip。
- 最后一个拍点、结尾稳定帧和最终帧；结尾不能无依据地保留长时间静态画面。
