## {{STAGE:voice}}：TTS 和断句校对

所有内置配音服务都经 OnSet 的 `voice_synthesize()` 生成，按 `onset.conf` 的 `TTS_PROVIDER` 选择服务。编排工具只负责文稿、音色与表达意图，不直接执行配音服务的命令，也不拼接模型目录、参考音频、底层参数或解码脚本。

| 取值 | 服务 | 音色与时间戳 |
|---|---|---|
| `minimax` | MiniMax | 服务音色 ID；保留真实句级时间戳，精细时间轴仍需对齐 |
| `bailian` | 阿里云百炼 | 服务音色 ID；需强制对齐 |
| `edge` | 微软 Edge 在线语音 | 免鉴权，适合预览和草稿；原始句级时间戳只作参考 |
| `elevenlabs` | ElevenLabs | 服务音色 ID；返回可交给 `align_build()` 的字级 `alignment` 文件 |
| `tencent` | 腾讯云语音合成 | 数字 VoiceType；OnSet 自动按请求上限分段、转换和拼接，需强制对齐 |
| `mlx` | 本机 MLX | Apple Silicon；预置音色；需强制对齐 |
| `breeze` | 本机 Breeze TTS 2 | 使用音色库名字；Apple Silicon 或已准备 CUDA 的 Windows；需强制对齐 |
| `x:<插件>` | 第三方插件 | 使用本说明末尾「第三方站」登记的配音工具 |

配音与对齐工具都是前置资源，由客户端工具准备页安装。配音的模型与运行环境由 OnSet 检查并选择本地版本；缺失时回工具准备页处理，不在制作途中下载、安装或升级。配音服务凭据只保存在服务自己的用户级配置或系统钥匙串，不写进项目、文稿、工具参数或日志。未登录时请用户完成对应服务的登录后继续，不让 AI 收集密钥或拼登录命令。

### 试听和正式生成

1. 用 `voice_catalog()` 查看当前服务的音色。Breeze 返回用户音色库；已有默认音色时直接用它，用户要求换声音时再挑。音色 ID 记入 `production/production-config.json` 的 `ttsVoiceId`，Breeze 的库名记入 `ttsVoice`。
2. Breeze 需要新声音时，调用 `voice_design({"instruction":"一位三十多岁的男性，声音沉稳清晰，语气平静、真诚","text":"大家好，欢迎来到今天的节目。","output":"production/audio/try-01.wav"})`。描述只用于设计试听，文字应能念 5–25 秒；也可用 `studio_show({"page":"voice"})` 请用户录音、上传或自己挑选。
3. 用户确认后，用 `voice_save({"name":"沉稳男声","audio":"production/audio/try-01.wav","text":"大家好，欢迎来到今天的节目。","source":"designed"})` 保存声音，文字必须与试听逐字一致；用户要求以后默认使用时才设 `make_default`。正式配音始终克隆库里的声音。
4. 用 `align_text()` 从终稿生成 `production/audio/tts-text.txt` 和 `production/audio/align-text.txt`，然后调用 `voice_synthesize({"text_file":"production/audio/tts-text.txt","voice":"<音色 ID 或库名>","output":"production/audio/voice.wav"})`。Breeze 留空 `voice` 会使用默认音色，参考音频和逐字稿由 OnSet 原样读取。
5. 音色尚未确认时，用同一段 10–20 秒代表性文案生成 2–3 个试听版本；确认音色、语速后再整篇生成。重新生成使用新文件名，例如 `voice-v02.wav`，不能覆盖已确认的配音。

长任务使用 OnSet 的 `job_wait` 等待，取消用 `job_cancel`，不额外启动终端进程。工具统一输出 48kHz 双声道 WAV，并返回 `audio`、`report` 和 `sources` 路径。同名 `.tts/` 目录保存朗读文本、原始音频、服务响应、原始时间戳、分段实际时长与偏移和生成参数；生成报告引用这些产物，不记录底层命令。

优先按完整语义段落调用，避免按字幕行生成造成语调碎裂。多段文稿（如 `align_text()` 导出的 `tts-text.txt`，每段一行）交给 `voice_synthesize()` 时，OnSet 默认按段落合成并在段间插入 450ms 静音停顿，让换段有自然呼吸和画面转场空间；需要更紧凑或更舒缓的段间间隔时，可显式传 `paragraph_pause_ms`（0–3000，0 表示整篇一次合成不补段间静音）。Breeze 按语气分组合成时，同一组使用同一个库名；`instruction` 只写语气、情绪、语速，不改音色。语气说明与段落范围记进 `production/audio/directions.md`，先对有指导的段落试听比较，再按顺序拼接。声音事件仍写在终稿，`align_text()` 保留在 TTS 文稿里、从对齐文稿中去掉。

### 语速与发音控制

`speed` 通常是倍率，未指定为正常速度，不把某个试听值永久写死。腾讯沿用服务的 -2..6 刻度（0 正常）；Breeze 和 MLX 不接受数值语速，用 `instruction` 指导，例如「语速放慢，语气沉重、克制」。不支持的参数会明确报错，不能悄悄忽略。

MiniMax 的 `pronunciation` 是替换列表，例如 `["2025年/二零二五年", "处理/(chu3)(li3)", "API/诶屁爱"]`；整词匹配，不只替换一个多音字。英文用 IPA、缩写可展开为读音，中文多音字用带声调拼音。百炼用 `ssml: true` 开启 SSML，中文 `<phoneme>` 使用 `alphabet="py"`，英文使用 `alphabet="ipa"`；其余服务用终稿的 `<显示|朗读>` 标记改写朗读侧。四位年份直接写成逐位汉字，字幕仍显示原文。

- 正式生成前，先扫描终稿全文（特别是全部 `@{id}…@{/id}` 受保护短语——`align_text()` 送给 TTS 时会剥掉短语标记，TTS 看不到它们），把容易误读或读断的英文单词、英文词组、英文缩写、产品名、模型名、专有名词、数字和多音字逐一列出并确定预期读音，再写入对应 TTS 的发音控制；同一词出现多次也要统一。不要靠生成后试听再补。
- 四位数年份一律逐位读：`1972 年` 读「一九七二年」，`2025 年` 读「二零二五年」，`2026 年 2 月` 读「二零二六年二月」，`1970 年代` 读「一九七零年代」；不得读成「一千九百七十二年」「两千零二十五年」。扫描时把全文每一个四位年份都列入发音控制，不要交给 TTS 自行判断：同一音色对不同年份、不同上下文的处理并不一致。其余数量数字（`16 个`、`815 字`、`64KB`）仍按数值读。
- 多音字按上下文定读音，不要交给 TTS 自行判断：同一个字在不同词里读法不同，例如「过分」读 guò fèn、「十分」读 shí fēn，「重要」读 zhòng、「重新」读 chóng，「行业」读 háng、「行动」读 xíng。扫描时逐句看多音字，把每一处的词和预期拼音（带声调）列进生成报告；同一个词全篇读法一致。钉住读音的写法分两类：
  - 能写拼音的路径（MiniMax 的 `pronunciation`、百炼 SSML 的 `alphabet="py"`）直接写拼音，见下面各自的参数。`pronunciation` 会替换全文所有匹配处，匹配串写整个词（`过分`），不要只写一个字（`分`），否则别处的「分钟」也被改读。
  - 其余路径（Edge、MLX、Breeze、腾讯云、ElevenLabs）在终稿里写 `<显示|朗读>` 标记，朗读侧换成读音相同、但只有这一个读音的字，例如 `<过分|过份>`、`<重新|虫新>`。替换字要和原字同声母、同韵母、同声调；整词找不到合适的写法时，换掉整个词（朗读侧写成同音的另一个词）。字幕照样显示原文，对齐用的是朗读侧，所以不影响时间轴。
- 用 `align_text()` 从终稿生成 `production/audio/tts-text.txt` 与 `production/audio/align-text.txt`：标记已换成朗读写法，`#` 标题行已去掉。送进 TTS 的是 `tts-text.txt`，{{STAGE:timeline}}强制对齐用 `align-text.txt`（去掉了声音事件，没有事件时两份相同）；各路径的发音控制（`pronunciation`、SSML）只处理文本改写也读不准的词。语法写错时它会报出行号和列号。
- 生成报告保留参数、原始音频和服务返回的时间戳，不得手工伪造时间戳。
- 除 ElevenLabs 的字级 `alignment` 可以直接交给 `align_build()` 外，其余路径的 `voice.srt` 均由{{STAGE:timeline}}的强制对齐生成；句级时间戳只作参考。到时间轴阶段结束时必须得到 `production/audio/voice.wav` 与毫秒精度的 `production/audio/voice.srt`。

### 断句检查

重点检查：

- 产品名、模型名或短语是否被错误拆开。
- "主语—谓语""动词—宾语""条件—结论"是否被不自然地切断。
- 数字、英文缩写、专有名词和多音字是否读对（多音字对照生成报告里列的拼音逐个听）；英文词应为标准英文发音，不能是拼音近似的中式英文。
- 每个四位年份是否逐位读出（「二零二五年」），没有读成「两千零二十五年」。
- 长句是否有足够呼吸。
- 句尾是否留出画面展示时间。

发现断句或发音问题时，先修改稿件标点、分段或发音控制，再重新生成受影响段落；不要只靠后期剪切掩盖。发音控制必须覆盖生成前扫描列出的全部易误读词，同一词出现多次也要统一。

### 配音审核关卡

正式时间轴冻结前，至少交付：

- 完整配音试听文件。
- 本次音色和参数。
- 断句与发音检查结果。
- 需要人工确认的疑点。

试听必须同时覆盖开场、信息最密集段落、英文或数字最多的段落和结尾。仅听一小段不能证明整篇口播速度合适。语速确认必须早于正式时间轴和镜头渲染。

正式配音一旦变更，旧的 SRT、词级对齐、总帧数、分镜、镜头时长、cue sheet、混音和候选视频全部标记为失效并重新生成；不得把旧画面整体拉伸去追新配音。
