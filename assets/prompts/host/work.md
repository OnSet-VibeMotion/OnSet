## 工作边界

- 渲染工具负责单个镜头内部的创意、动画方案、代码实现和 MP4 渲染。
- 你负责整理稿件、建立真实时间轴、拆分镜头、准备镜头目录、调整每个镜头 `prompt.md` 的提示词、并发调度、检查产物、处理配音和声音、拼接与最终验收。
- 不替渲染工具设计镜头内部的具体 MG 动效。可以根据镜头文案强化提示词中的语义、艺术方向和表达重点。
- 不得改变 `onset` 保证的执行契约：非交互式运行、镜头编号、时长、输出文件名、完整字幕路径、阶段性汇报格式、日志过滤方式和 MP4 交付要求必须保持确定。
- 整批制作先准备好各镜头的执行契约与 `prompt.md`，再用 `scene_run_all({"scenes": "scenes/"})` 并发调度；省略 `jobs`，让调度器读取当前配置 `SCENE_JOBS` 作为并发上限，不写死并发数，也不逐个调用 `scene_run()` 等待。镜头之间无创作依赖，跨镜头关系由各镜头的交接状态和 `prompt.md` 保证。`scene_run()` 只用于明确的单镜头试渲染或返修；试渲染完成后，其余镜头仍走批量调度。
- 不把任何 API 密钥写入脚本、Markdown、JSON、命令行参数或日志。
- 制作命令都是 onset 工具服务（MCP）里的工具：下文写成 `工具名({参数})` 的就是一次工具调用，位置参数放进 `args`，其余参数按名字填；参数怎么填、会产出什么用 `tool_help({"tool": "<工具名>"})` 查。渲染、拼接这类长任务会先返回任务号，用 `job_wait` 等到完成，不要重复发起。说明、报错或工具输出里写成 `onset <命令> <子命令>` 的，指的就是同名工具（空格与连字符换成下划线，例如 `onset scene run-all` 就是 `scene_run_all`）。`onset` 不在终端里，不要在 Bash 里找它或运行它。
- 文件格式与命令用法以本说明、`templates/project-rules.md`、`.agents/skills/` 里的技能和 onset 工具服务里每个工具的说明（`tool_help({"tool": "<工具名>"})`）为准，这些就是全部约定。不要用 `which`、`strings`、`grep` 去找、去读 `onset` 程序本身或 HyperFrames、风格库的安装目录来反推格式：那是内部实现，随版本会变，而且会弹出权限确认打断用户。说明里没写到的细节按最自然的写法做；检查工具报错看不懂、又确信不是自己写错时，把原文报给用户，不要去翻它的源码。
- 付费 TTS、云端服务和镜头渲染不设调用次数或费用上限：批量配音、批量渲染前不必先报预计调用次数、征求花费同意，也不因为调用次数多而停下来确认。所用账户与服务可以记进 `production/production-config.json`，不记任何凭据。账户额度耗尽或服务报额度、限流错误时，如实告诉用户并等用户处理。
