# 新增一个 AI CLI

> 从仓库根 `AGENTS.md` 拆出的开发约定。总则、命令与各份文件的索引见根 `AGENTS.md`；文中「见「某节」」指的节都能从那份索引找到。

工具矩阵散落在八个文件，加一个工具必须十一处同步改，漏一处会在运行期才炸（制作人 `director` 不是外部 CLI，它的约定见「制作人（自带的编排工具）」）：

| 位置 | 作用 |

| `packages/engine/src/tools/tools.ts` `orchestratorInvocation` | 编排调用的命令行、prompt 传递方式（stdin 还是参数）、结构化输出参数、会话参数（新会话 / 续接），以及把 `OrchestratorAccess` 译成该工具的白名单 |
| `packages/engine/src/tools/tools.ts` `presetSessionID` | 该工具能否由调用方预先指定新会话 id；不能的（codex、opencode）要从输出流的第一条事件里读 |

| `tools.ts` 的 `rendererInvocation` / `orchestratorInvocation`（或 `acp.ts`、`codexapp.ts`） | 挂上 onset 的工具服务（见「onset 的工具服务」），并放行它的工具；`toolsmcp.integration.test.ts` 的 RealToolsMCP 加上这一家 |

Qoder 有两个版本，账号与服务互不相通，算两个工具：国内版 `qoder`（命令 `qoderclicn`，状态在 `~/.qoder-cn`）与国际版 `qoder-intl`（命令 `qodercli`，状态在 `~/.qoder`）。两者的参数、输出流、会话、`--settings` 写法与项目技能目录（`.qoder/skills`）逐项相同（1.1.89 实测 `--help` 只差国内版多一个 `config` 子命令），所以除命令名（`tools.qoderBinary`）外一律按同一家处理（`tools.isQoder`，各处 `case 'qoder': case 'qoder-intl':`）；沙箱两边的状态目录都放行、两边的用户级技能都藏起来。改 qoder 的调用时两版都要用真实 CLI 跑一遍（`ONSET_TEST_AGENT_TOOLS=qoder,qoder-intl`、`ONSET_TEST_TOOLS_MCP=qoder,qoder-intl`）。

Qoder 的模型表不用 `--list-models`（只有名字），由 `tools/qodermodels.ts` 的 `fetchQoderModels` 经 `<命令> --sdk` 的三步握手取：`daemon.initialize`（`daemon_protocol_version: 2`、能力 `multi_session_v2`、`auth: {type: "qodercli"}` 沿用命令行已登录的账号）→ `daemon.open_session`（`worker_args` 不能为空）→ 带会话号的 `initialize`，回应的 `models` 有额度倍率（`priceFactor`）、打折前倍率与活动、每个模型的推理档位与默认档、上下文长度与默认长度；不发提示词、不花额度。说明文字不在协议里，读 `<状态目录>/.auth/dynamic-texts.json` 的 `modelSelector.item.<模型键>.markdownDescription`（中文优先，链接去掉）。读不出来（没登录、版本不认）时退回 `--list-models`。不推理的模型 `efforts` 给空数组，界面据此不出推理强度。弹出框（`ModelPicker`）每行右边是额度（`8.00x 额度`、划掉的原价、免费、活动），推理强度与上下文长度按所选模型收窄，「默认」一段写明模型自己的默认档。改握手时用真实 CLI 核对（1.1.89 实测：国际版 17 个、国内版 14 个模型）。

MiniMax Code（`mcode`，npm 包 `@minimax-ai/code`，0.6.12 实测）与别家几处不同，改它的调用前先看这几条：输出流是它自己的 `exec --output-format stream-json`（每条带 `schemaVersion`、`runId`、`sessionId`，`item.*` 的 item 是 reasoning / agent_message / tool_call，工具状态 2 成功、3 失败，待办工具 `todowrite`；`studio/activity.ts` 先按 `schemaVersion` + `runId` 认它，不然 `turn.*` / `item.*` 会被当成 codex），会话号只能从流里读、续接用 `--session`；模型写成 exec 的 `服务商/模型`（`minimax/MiniMax-M3.1-Flash`，`#变体` 会被忽略），ACP 里的值是 `m:<服务商>:<模型>:v:<变体>`，由 `agentrun/acp.ts` 的 `configureMcode` 换算；推理强度只有部分模型能调，不支持时整轮报错，模型表（`tools/mcodemodels.ts`，ACP 握手读会话选项，不发提示词）按模型给档位。exec 没有 MCP 参数、没有命令白名单（权限只有 `smart` / `full` / `off`），只读工作目录的 `.mcp.json`：渲染器由 `scene.run` 的 `stageMcodeMcp` 在镜头目录里临时写一份（别人的 `.mcp.json` 不覆盖、报错），客户端里的编排不论安全与否一律走 `mcode acp`（`interactiveInvocation`），在会话里切 `permissionMode`（用户自己的 `config.yaml` 常是 `bypassPermissions`）。它的 Ask 模式自己判定哪些要问（部分交给云端），白名单外的 `brew` 有时照样直接跑，不能当闸门：安全模式下 `mcodeAskBash` 往 `<数据目录>/sessions/<会话>/permission.json` 加一条不带命令的 `ask` bash 规则，每条 shell 命令都来问、白名单由 `commandAllowed` 答。ACP 不报 token（`usage_update` 只有上下文占用），这几轮用量记为未读到。技能：项目里认 `.agents/skills`、`.minimax/skills`、`.claude/skills` 并一直往上找到 git 根（没有 opencode 那样按名字收窄的开关），镜头技能链进 `.minimax/skills`；沙箱放行写 `~/.minimax` 与同级的锁 `~/.minimax.lock`（写不了报 `agent_name_conflict_migration_failed:lock`），藏起 `~/.minimax/skills`、`plugins`，`agents/` 不能藏。数据目录可由 `MINIMAX_DATA_DIR` 改，里面有登录态。它会把「记住某个词」这类话写进自己的 `~/.minimax/memory/`，跑真实 CLI 测试后看一眼。改它的调用后用真实 CLI 跑 `ONSET_TEST_AGENT_TOOLS=mcode`、`ONSET_TEST_INTERACTIVE_TOOLS=mcode`、`ONSET_TEST_TOOLS_MCP=mcode`、`ONSET_TEST_RENDERER_RESUME=mcode`。

Antigravity CLI（`agy`，v1.5.13 实测）的约定：headless 输出流为 `agy -p <prompt> --output-format stream-json`（每行带 `event`：`init`、`step_update`、`result`，`conversation_id` 从流里读、续接用 `--conversation`；`agent_response` 的 `text_delta` 按 `step_index` 拼到 `state === "DONE"`；`result.usage` 的 `input_tokens` 不含 `cache_read_tokens`、`output_tokens` 已含 `thinking_tokens`，续接后整个会话累计）。Windows 长提示词改用 `--input-format stream-json` 经 stdin 发 `{"event":"user","message":{"content":…}}`。headless 没有 `--mcp-config` 参数，从工作区 `.agents/mcp_config.json` 读 MCP（默认超时 180 秒，这里显式写 `timeoutSeconds: 720` 并把渲染档位 5 个工具标为 `eager: true`）：渲染器由 `scene.run` 的 `stageAgyMcp` 在镜头目录里临时写一份（不覆盖别人的配置），客户端里的编排不论安全与否一律走 `agy acp`（不安全模式带 `--dangerously-skip-permissions`，安全模式在会话里切 `mode=accept-edits`；MCP 服务经 `session/new` / `session/load` 传，对 `onset` 工具服务在 `session/request_permission` 里自动放行；命令参数在 `rawInput.CommandLine`，用量在 `session/prompt` 返回的 `usage` 里且 `outputTokens` 已含 `thoughtTokens`）。`mcp_onset_<工具>` 与 `call_mcp_tool` 在解析器和 ACP 翻译器里统一规范成 `mcp__onset__<工具>`。模型列表跑 `agy models`，同基础模型的多个推理档位变体合并成基础模型并带 `efforts` / `defaultEffort`；ACP 与 headless 同时认基础模型名加 `--effort` / `thought_level`，也认带档位的完整 slug。技能链进镜头目录 `.agent/skills`（避免与 `.agents/mcp_config.json` 冲突，`.agent` 在 `ProjectSkippedDirs` 中），沙箱放行写 `~/.gemini/antigravity-cli`，藏起 `~/.gemini/skills`、`~/.gemini/config/skills`、`~/.gemini/config/plugins`、`~/.gemini/config/mcp_config.json` 与 `~/.agents/skills`。改它的调用后用真实 CLI 跑 `ONSET_TEST_AGENT_TOOLS=agy`、`ONSET_TEST_INTERACTIVE_TOOLS=agy`、`ONSET_TEST_TOOLS_MCP=agy`、`ONSET_TEST_RENDERER_RESUME=agy`。

安全模式的权限模式必须实测能跑通渲染命令。claude 的 `acceptEdits` 只自动批准文件编辑、拦下所有 Bash，而 `-p` 下没人批准，渲染器会执行不了 `onset hyperframes render`；`scene.rendererAccess` 列出要放行的最小命令集（`onset hyperframes`、`ls`、`ffprobe`）与技能目录读取，`.env` 始终禁读。渲染器在 macOS 上一律套系统沙箱（`scene/sandbox.ts`，`sandbox-exec`，`scene.run` 在 `lookPath` 之后包上，五家都套，不安全模式不套）：边界是目录，不是命令白名单——写只有镜头目录、临时目录、渲染工具自己的状态（`sandbox.rendererHome`：claude 的 `~/.claude` 与 `~/.claude.json*`、codex 的 `~/.codex`、codebuddy 的 `~/.codebuddy`、opencode 的四个目录、qoder 的 `~/.qoder-cn` 与国际版的 `~/.qoder`）与 `~/.cache/hyperframes`；读在家目录里只有本项目、渲染工具与 onset 的数据目录、`~/Library`、PATH 里家目录下的项连同上一层（asdf 的 shim、`~/.local/bin/claude` 都指向上一层里的真身）与 `.tool-versions` 这类配置文件；任何 `.env` 与制作人的凭据目录读写都拒，各家用户级的技能与插件（`rendererHome().hidden`）读不到。沙箱对渲染器起的每个子进程都生效，所以各家自己不再拦命令（`RendererAccess.osSandbox` → claude、qoder `--dangerously-skip-permissions`，codex `--dangerously-bypass-approvals-and-sandbox`——codex 自己的沙箱也是 sandbox-exec，套在里面起不来——codebuddy `-y`），python3、sips、组合命令都能跑。规则的坑：Seatbelt 里同一路径上更具体的操作压过通配，`deny file-read*` 盖不过前面的 `allow file-read-data`，凭据的收回必须写成 `deny file-read-data`（实测）。`sandbox.test.ts` 在 macOS 上真跑一遍。以前白名单下 qoder 一个镜头 41 次调用里 6 次被拒（python3 裁图、sips、`cd … &&`），渲染途中没人能批准，只是白耗几轮。其他平台照旧：claude 系 `acceptEdits` 加 `--settings` 白名单（qoder 认 claude 的 `permissions` 写法，与关掉懒加载 MCP 合在一份 JSON 里；以前 qoder 用的 `dont_ask` 连镜头目录里写文件都拒，渲染器一个 `index.html` 都写不出来，2026-11 实测）。

渲染器只给几样内置工具、只挂 onset 的工具服务（`tools.ts` 的 `RendererBuiltinTools`）：claude 与 qoder 加 `--strict-mcp-config --tools Bash,Read,Write,Edit,Skill`，codebuddy 只加 `--strict-mcp-config`（它的 `--tools` 连 MCP 工具一起藏掉，实测）。不限的话 claude 带着用户自己装的 MCP、claude.ai 连接器与 Cron、Workflow 这类工具共 117 个，第一次调用 47.6K token，限了之后 11 个、24.1K（2026-11 实测）。

技能走各家自己的 Skill 工具，只给镜头要用的那几个：`scene.run` 在启动前把提示词里点名了目录的技能（`scene.stagedSkills`）以符号链接放进镜头目录里那家读项目技能的位置（`rendererStageDir` = `rendererSkillDirs` 的 project：`.claude/skills`、`.codex/skills`、`.codebuddy/skills`、`.opencode/skills`、`.qoder/skills`，2026-11 逐家实测能发现），渲染结束删掉，上次没删干净的（可能是另一家的）在下次解析技能前清掉（`unstageRendererSkills`，不然 resolveSkill 会找到这些链接）；这几个目录都在 `fsutil.ProjectSkippedDirs` 里，不算项目文件的改动。用户级的技能由沙箱藏起来（qoder 另加 `--setting-sources project,local`，连用户级钩子一起不进渲染）；opencode 会从镜头目录一直往上找到项目根的 `.agents/skills`，所以 `tools.rendererEnv` 另给 `permission.skill`：`*` 拒绝、只放行 `RendererAccess.skills`（实测项目根与用户级的都不再出现）。opencode 还按 `PWD` 而不是进程工作目录定项目目录，`scene.run` 把渲染器的 `PWD` 设成镜头目录（不安全模式照搬过来的 PWD 会让它写到镜头外面，实测）。经链接改技能文件改的是真文件：沙箱下技能目录本来就不可写，其他平台由 `claudeSettings` 对技能目录（`readDirs`）拒绝 Edit / Write（规则按真实路径匹配，链接绕不过去）。`stageskills.test.ts` 钉着只链点名的、各家各放一处、清理只删自己建的。

客户端里的 claude 与 qoder 编排工具遇到白名单外的调用时不直接拒绝，而是问界面上的用户：`orchestratorInvocation` 给它们加 `--mcp-config`（`onset studio permission-mcp`，`OrchestratorOptions.permissionPrompt`）与 `--permission-prompt-tool mcp__onset_studio__ask`（claude 还要 `--permission-prompts host`；qoder 的这个参数帮助里没列，实测可用）；审批服务把请求写进这一轮收件目录的 `permissions/` 子目录（`studioview/permissions.ts`），后端轮询到就发 `permission` 事件、界面在输入框上方弹卡片，答复经 `POST /api/sessions/{id}/permissions/{请求}` 写回（`studio/permissions.ts`），这一轮结束时没答的一律答成 `expired`。「以后都允许」把命令前缀记进项目的 `production/studio/permissions.json`，下一轮并进白名单。设置里的「自动批准」（`AUTO_APPROVE`，全局或这个项目，卡片上的「以后都不用问」打开全局的）开着时，`pollPermissions` 收到请求直接答 allow、不发 permission 事件，只在这一轮里发一条「已自动允许：…」的 notice；五家的审批都落到同一个收件目录，所以只此一处。它只回答「要不要问」，工具自己的沙箱照旧（用户嫌审批太多次）。codebuddy 不认 `--permission-prompt-tool`、codex exec 不能中途审批、opencode 的 `run` 根本不拦命令，所以客户端里（`agentrun.Spec.ask` 给了、安全模式）它们改用双向协议：`tools.interactiveInvocation` 选 ACP（`codebuddy --acp` 沿用 acceptEdits 与白名单 `--settings`；`opencode acp` 经 `OPENCODE_CONFIG_CONTENT` 把 bash 设成 ask，合并用户自己的这个变量）或 `codex app-server`（`thread/start` 给 `approvalPolicy: untrusted`、workspace-write 沙箱、网络与可写目录），由 `agentrun/acp.ts`、`codexapp.ts` 在 `interactive.ts` 的进程外壳上跑。对方的审批请求先过白名单（`commandAllowed`，去掉 codex 的 `zsh -lc` 包装），白名单外的经 `spec.ask` 写进同一个收件目录，后面与审批 MCP 一模一样。约定：ACP 的「总是允许」只答 `allow_once`、codex 拒绝答 `decline`（不打断整轮），「以后都允许」只由客户端记；续接用 `session/load` / `thread/resume`，ACP 续接时对方重放的历史不当成这一轮的事件；opencode、codebuddy 被拒后会直接结束这一轮，`acp.ts` 在对话里补一句说明。三家用旧的一次性模式建的会话都能在新协议下续接（2026-11 实测），所以升级不会让已有会话断掉。`onset run` 与 `--unsafe` 仍走一次性模式。离线测试用 `agentrun/testdata/fake-acp.mjs` 与 `fake-codex-app.mjs`，e2e 的 `fake-bin/opencode` 复用前者；`--mcp-config` 吃多个值，后面必须紧跟一个选项，不然会把提示词吞掉。改了这条链要用真实 CLI 跑一遍：claude 与 qoder 照下面的 RealCLI，三家双向协议用 `ONSET_TEST_INTERACTIVE_TOOLS=codex,opencode,codebuddy npx vitest run --root packages/engine src/agentrun -t RealInteractive`（opencode 默认模型不可用时加 `ONSET_TEST_OPENCODE_MODEL`）；fake 只模拟协议。

编排工具同理，`orchestratorAccess`（`config/providers.ts`）列出它要放行的命令：基础命令（`orchestratorBaseCommands`，**不含 `onset`**——onset 只经工具服务调用）加当前对齐工具的命令（`Aligners` 的 `command` 字段）；TTS 命令只由 OnSet 配音适配器运行，不放行给编排工具。各家的权限模式实测结果不同，改之前先读 `orchestratorInvocation` 的注释：qoder 的 `dont_ask` 连写文件都拒；codex 没有命令白名单，靠沙箱，而沙箱默认断网会让 TTS 失败；opencode 2.x 只读项目目录里的 `opencode.json`，规则集拦不住命令，写成全拒时无头运行会直接挂起，所以 `opencode run`（`onset run`）在安全模式下不加限制，README 里写明了；客户端里的 `opencode acp` 经 `OPENCODE_CONFIG_CONTENT` 把 bash 设成 ask，白名单外的命令照样会问（实测 2.1.0 有效）。

Qoder 编排在安全模式且挂有 onset 工具或审批服务时，额外通过 `permissions.deny` 拒绝文件工具修改项目 `scenes/` 与 `production/shared/` 下的 HTML/CSS/JS/TS 实现文件（`tools.ts` 的 `qoderOrchestratorSettings`）。Qoder 的路径写入规则用 `Edit`，同时覆盖 Write；模式以 `//` 开头写绝对路径，不能使用没有根目录的多段 glob（实测未拦住）。`prompt.md`、`scene.json` 和渲染器权限保持原样。此规则不限制 Bash/脚本，不能当作系统沙箱；复制、同步和补丁仍由每轮职责说明约束。`RealToolsMCP` 中的 Qoder 文件权限用例必须在本机通过。

片场启动的 Claude 编排会话通过 `--disallowed-tools mcp__chrome-devtools__*` 禁用用户配置里的同名 MCP 工具。每轮启动都带这项限制，续接和不安全模式也一样。镜头质检用片场自己的抽帧工具，避免 DevTools 接入用户已有的浏览器标签页。

改了任何一家的调用参数或解析器，都要在本机跑一遍真实 CLI 集成测试（`packages/engine/src/agentrun/integration.test.ts`）：

```bash
ONSET_TEST_AGENT_TOOLS=claude,codex,qoder,codebuddy,opencode,mcode,agy npx vitest run --root packages/engine src/agentrun -t RealCLI
```

它对每家跑两轮，第二轮续接后要答出第一轮让它记住的词。每次都是真实模型调用，CI 不跑。
