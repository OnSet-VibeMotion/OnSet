# Windows 全量测试与整片监控

基线为 `044ab05`。仅修改 Windows 的运行分支与相应测试夹具；macOS/Linux 的原有启动、媒体调用和项目指纹规则保留。单片内容、模型和私人日志不进入本仓库。

## 已定位的问题

| 原因 | 修复与验证 |
| --- | --- |
| Unix 假工具在 Windows 下无法查找或启动，甚至落到真实的开发者工具 | 测试专用的 `.cmd`/Node 入口；需要原 shell 语义的夹具显式使用 Git for Windows 的 sh。假 Codex 优先命中，不调用真实模型。多行提示词同时覆盖参数与 stdin。 |
| 媒体、歌曲、对白和风格准备中的部分路径直接 spawn `.cmd` | 仅 Windows 使用现有 cmd-shim 解析或进程组执行器，保留 Unicode、多行参数和退出码；原 Unix 分支不变。测试实际启动临时工具，验证 stdout、stderr、退出码及取消时父子进程均结束。 |
| 歌曲路径校验按 `/` 拆分，漏掉 Windows 反斜杠路径中的 junction 祖先 | Windows 先规范分隔符、拒绝盘符相对路径，再逐层检查；目录链接测试确认没有项目外写入。 |
| 同一秒连续调用批量队列时，日志名冲突报 `EEXIST` | Windows 默认日志名加独立随机标识。冻结测试时钟连续调用两次，各自产生完整日志，第一份字节不变；显式指定已有日志仍拒绝覆盖。记忆批次编号不改。 |
| POSIX 权限位、路径分隔符、特权文件链接和非法 Windows 文件名被当作统一平台契约 | Windows 测试改用实际读写能力、可用的目录 junction 和合法文件名；原 Unix 权限断言保留。链接逃逸测试仍执行，无需管理员权限。 |
| 黄金文件中的技能路径本来就按操作系统分隔符生成 | 单独保存经审核的 Windows 黄金文件；逐项确认非提示词输入摘要、场景数据与 JSON 不变。原 Unix 黄金文件和产品生成逻辑不改，避免让已完成镜头变成 Stale。 |
| 帮助检查从开发命令路径反推工具名，遗漏 Windows 别名；Windows 组与对齐示例缺失 | 工具别名从操作表读取，补齐 Windows 专用说明与工具调用示例。流程模板检查排除另行注入的 Windows 执行说明。 |
| 临时目录泄漏测试统计了其他并发工作者的目录 | Windows 给该次安装测试使用独立 TEMP 范围，只检查自己的临时目录。 |
| 含长段间停顿的整段 FunASR 输出文字匹配100%，但真实语音起点仍提前约1秒 | Windows 对齐操作新增可选的原始 TTS 拼接清单：绑定完整音频、终稿与分段摘要，逐样本证明拼接，仅一次初始化模型逐段推理，再用真实采样位置还原。分段模式必须文字匹配100%、没有插值、完整音频检查通过；不猜切点、不平移错误时间戳、不放宽阈值。原始全篇模式、Mac/Linux 对齐路径保留。 |

## 验证范围

采用与桌面内置 Node 24 同代的本机 Node 24.22.1，使用已安装的 ffmpeg、ffprobe、Git 和 npm。最初未规范工具环境、使用 Node 26 的复测出现引擎 57 项、CLI 6 项失败，包含环境差异；没有把这些全部当成产品缺陷，也没有通过修改 macOS/Linux 行为让 Windows 通过。

- 引擎全量：1,327 项通过，0 失败，34 项原有条件跳过。
- CLI 全量（含新分段清单回归）：198 项通过，0 失败，8 项原有条件跳过。
- 引擎/CLI、桌面主进程和渲染端类型检查通过。
- 隔离运行包构建成功；真实 Chromium/FFmpeg 的 119 帧 GPU 冒烟测试通过，实际两个 worker，约 14 秒，编码约 0.1 秒。
- 不额外增加跳过用例。原有跳过主要涉及联网下载、真实模型服务、上游完整资源、macOS 沙箱、POSIX 权限，以及未准备的 rsvg-convert/ImageMagick 等可选工具。全量测试通过不表示这些可选集成已验证。

## 原始分段对齐的实测

64.378333秒的已批准配音，在隔离副本内使用8个原始 TTS 段及真实拼接采样位置：一次初始化 FunASR，核心推理及输入校验8.42秒，原始音频与48kHz试听副本的独立检查均通过；文字匹配100%，插值0。新操作的桌面 Node 完整调用为10.93秒（同时有独立GPU冒烟检查），重复相同成功输入复用为0.229秒。修改某分段的PCM并同步其摘要后仍因完整拼接验证失败而拒收，再次相同失败输入立即停止，不重新试错。生产源文件摘要不变。

新增清单解析回归测试覆盖：完整配音、终稿与分段摘要绑定，原始朗读字符覆盖，外部路径、重叠/非整数采样位置和错误采样率拒收。与既有 Windows 对齐及工具帮助一起9项通过。该结果验证对齐阶段，不等同于整片已提速或新运行包已部署。

## 现场补充修复
