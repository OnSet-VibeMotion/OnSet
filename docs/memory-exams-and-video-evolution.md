# 记忆总结与视频进化

视频经验应保存成能在新镜头中识别、执行并验证的制作决策。一条好的记忆说明何时采用什么做法、为什么有效、什么时候不适用，以及下一次怎样检查。经验数量、考试分数和一次通过率分别描述库的规模与检查结果；视频是否更好还需要人的观看评价。

## 记忆怎样参与制作

| 内容 | 来源 | 使用与验证 |
|---|---|---|
| 经历 | 正式渲染、事后检查、用户反馈 | 留下输入、问题、召回记录和出处，为总结提供依据 |
| 技术经验 | 同类失败与成功写法的对照 | 整理后进入试用，由相应校验器做带与不带的考试 |
| 画面技法 | 人判定的同题试镜胜负及评语 | 比较双方代码，提炼做法，由人评考试决定是否生效 |
| 长期偏好 | 用户明说的长期要求或反复反馈 | 明说的可直接生效；推测的须经用户确认 |
| 范例 | 人选出的试镜胜者 | 在已确认的学习关系中提供源码参考，同项目同镜头不给自己的答案 |

用户确认成片可用后整理本次经历。整理只产生试用经验，机器考试和人评考试按用户要求发起。正式渲染从生效快照按镜头特征、关键词及工具和模型范围召回，默认最多三条经验，同时受字数预算限制。总结应把有限的位置留给具体、相关、可以执行的提醒。

## 一条经验怎样写

description 用一句话概括“在什么情况下，采用什么做法”。正文在 600 字内写清以下内容，反例与正例不可缺少：

1. **适用条件**：描述能从镜头说明中识别的条件，配合已有的 features 与 keywords；不能只写“发生这个报错时”。
2. **具体做法**：给出操作、时序或参数关系。与画幅、帧率、文字量、口播有关的偶然常量，应转成随输入变化的关系。
3. **原因**：解释做法与问题之间的联系。观察到的差别和推测的原因要分开。
4. **边界**：说明不适用的场景，以及与项目强制要求冲突时如何让位。模型专属范围写进 applies_when，不混进正文。
5. **验证方式**：技术经验对应 checked_by；构图、节奏、层次等观看效果用人评对照验证。

例如，阅读时间经验不应停在“字幕要更清楚”，而应描述：有多个可读信息块时，按对应的口播时间依次展开；为每块文字保留符合阅读时间检查的可见区间；先满足阅读停留再安排退出动效。反例给出所有信息短暂同时出现的做法，正例给出分块展开与停留的时间轴，并说明纯装饰元素不受这条阅读规则约束。具体阈值应引用实际检查规则，不能从单个镜头猜一个通用秒数。

同类经验优先修订，保留旧版仍成立的细节与校验器。不同的可检验问题不要为了省条数硬并成一条。一次修改要求留在当前任务；反复出现也只是长期偏好的候选信号。

## 总结依据怎样使用

同一镜头更晚的成功渲染可以提供修复参考；更早的成功不能说成“后来改对了”。其他镜头至少要有共同特征才适合做参考，同一个工具制作并不足以说明可比。

整理工作目录只在当前渲染记录指纹仍相符时复制成功版源码。失败版源码缺失时，可以引用真实报错，不能编造当时的错误写法。成功版未被已有检查报告问题，不代表阅读时间、空白帧等所有检查都已经运行，更不代表其中某处代码差异就是改善的原因。

人评互学从胜者与学生的对照里提炼构图、信息展开、层次和节奏等做法。人的评语帮助定位差距，但源码中的每处差异仍需验证。范例保留具体实现，经验保存迁移方法，两者各有用途。

## 考试结论怎样解释

| 证据 | 能支持的结论 | 还需要验证的部分 |
|---|---|---|
| 旧题上试用组更好 | 本场旧题的机器检查结果改善 | 新镜头与其他项目能否受益 |
| 留出镜头未退步 | 这些留出镜头未出现相应通过率退步 | 是否产生了正向改善，以及更广的迁移范围 |
| 多条经验合考通过 | 这一组经验在本场整体有效 | 每条经验独立贡献多少 |
| 人评考试偏向带经验的作品 | 人更认可本场带经验的作品 | 多种题材及后续项目的稳定性 |
| 正式运行中问题减少 | 这些运行里的实际检查结果改善 | 输入难度、模型、技能与风格变化的影响 |

考试应保持同一份输入，两组按每次重复一一配对，实际模型一致。每条待考经验都必须在至少一对试用组中实际召回；被适用范围、三条上限或预算挡住的经验没有接受检验，不能随整组通过而生效。证据不足时保留原状态，单独考试或检查召回条件；缺格、重复格或模型不一致时整场无效。

阅读时间与空白帧经验必须接入对应事后检查，产物格式合格不能代替这些检查。阅读时间的可见区间由作答者申报，检查结果仍需结合画面对照；相邻镜头交接无法由单镜头重放充分判断。

两组都满分表示本场未发现额外改善，不能据此说经验有害或有效。重考前先确认检查覆盖原问题。跨层阅读顺序考试把实际烧录的字幕与标题放在同一局部帧时间轴：清单根部 `subtitle_cues` 列出实际烧录的字幕编号，没有烧录时填 `[]`。SRT 提供时间合同，不代表画面已有字幕；字幕可选时不能强迫作答者为了考试新增字幕，项目明确要求烧录时仍须覆盖本镜头字幕。每条实际字幕以 `role: subtitle`、`event_id: subtitle-<cues.index>` 和完整文字登记实际显示区间，检查器按冻结短语文字展开后与标题一起核对；不接受漏交、改字或冒报字幕。帧号、元素标识或帧率非法时，也不能因只考顺序而被过滤掉。字幕区间仍由作答者申报，机器并未独立测量视频像素。

经验应先判断做法是否有可行区间。例如，一行冻结字幕已同时包含多个短语，而标题又不能提前于自己的口播短语出现，单纯缩短标题入场未必能避免倒序。此时让字幕承担文字信息，改用图形、移动或指向关系承接语义，避免较晚重复展开前序标题；不能改冻结输入凑通过。验证时同时查看字幕开始帧与标题稳定帧，确认画面确实表达了信息，再评估机器检查是否改善。

实际使用中，优先对一条经验做对照，加入未参与总结且与其适用条件相符的镜头，再观察同工具和模型下的正式运行。重复考试能帮助观察波动；当前多数结果与平均得分规则不提供统计显著性保证。

## 整库处理与推广

先按修订关系梳理经验，保留旧版出处与考试记录，逐条核对错误标签是否还成立。已核实的人为批准例外不能被学成普遍禁令；没有批准证据时不能由作答者自行宣称豁免。镜头的局部事件清单与全片清单应分别说明坐标，不能复制一段会重复加全局起点的示例。

每条有效候选先写明适用条件、执行动作、不可行时的替代做法、批准边界和验证点。推广用不同镜头或项目中未参与这条经验总结的输入，在同一工具和模型范围内检验。客户端可选择“仅验证所选新镜头”；来源镜头会标注，且引擎拒绝把它们当作该模式的留出题。门槛仍是严格增益、无退步、真实召回及有效配对。

推广结果分别记录改善、持平、退步、基础设施无效与证据不足。两组均通过只支持这些新镜头没有出现相应问题，不能写成已证明额外收益。技术经验通过后才生效；明确的用户偏好保留原范围，不能因为机器渲染通过而自动推广成跨项目偏好。范例与旧版记忆保留修订出处，不以整库“全绿”为目标。

缺交、空清单、无法解析的短语合同或不成立的申报帧号，属于检查依据不完整，不能被计为已观察到的早露字或绑定错误，再靠试用组补交清单获得“质量增益”。此类格子使整场转为证据不足，保留记忆原状态。客户端对可确定识别的旧空清单记录也会作补充审计，显示原始记录仍然保留；发现仅凭此类证据生效的经验时，应撤回采用并重新验证。

共享技能中的 `SceneKit.phraseText` 将正文文字的短语绑定、初始隐藏、逐帧回跳门控与事件坐标导出放在同一份定义中。它支持 DOM 和独立画布文字层，局部事件与全片事件分别导出；`SceneKit.captions(...).events()` 从实际字幕布局导出文字与显示区间。稳定可读区间仍须如实申报，批准封面例外仍按项目要求处理。此工具用于减少机械错误，不能替代阅读时间、画面对照或经验的效果验证。共享资产随新项目下发；已有项目的技能不会被本次开发静默覆盖。

## 本次实现

- 故障整理与人评互学共用总结规范：`packages/engine/src/memory/writing.ts`。
- 成败对照排除同镜头更早的成功与无共同特征的其他镜头：`memory/consolidate.ts`。
- 考试增加配对、模型一致性、实际召回和必需事后检查约束：`memory/exam.ts`。
- 制作收尾提示词与进化页说明旧题、留出镜头、整组效果和观感的证据边界。
- 记忆卡片提供“只考这条”，把单条试用经验交给客户端当前的渲染工具做对照。
- 停用或被拒的经验也能重考：考试期间保留原状态，有效通过后才恢复并生成快照；未通过、无效、证据不足及仅预演时不恢复。
- “查找适用镜头”只读预演真实召回，列出匹配原因与预算限制，可将当前项目中选定的镜头加入考试。
- 记忆页逐题显示大尺寸视频对照、问题变化及同步播放和拖动进度。相同镜头、相同输入指纹的重复失败合并为一道题。
- 召回计数保留上次成功结果，刷新请求依次执行，暂时出错时标注旧结果，避免清空造成数字闪动。
- Windows 原子替换对 EPERM / EACCES / EBUSY 做有限退避重试，保持旧文件直至替换成功；避免进度文件短暂占用直接中断长时间考试，永久失败仍保留旧内容并报错。

这些改动使总结和考试的结论更可靠；视频质量提升仍应以真实项目中的对照画面、人的判断及后续运行结果评估。
